Agent-operable UI (WebMCP)

Browser agents are a second user of every web app now: Chrome’s WebMCP preview exposes navigator.modelContext, computer-use models drive pages through the accessibility tree, and in-page copilots call whatever a page lets them. Today they all guess what a widget does.

tekivex-ui/webmcp lets your components declare what they do — and runs every agent call through the same security kernel as the rest of the library.

Three discovery surfaces

navigator.modelContext.registerTool() when the browser has it, plus a frozen window.__tekivex_agent_tools__ snapshot and an inert <script type="application/tekivex-agent-tools+json"> manifest in <head> — so agents that only see a DOM dump still find the catalog.

Validation + sanitisation

Required keys, enums, bounds and patterns enforced; unknown keys rejected; __proto__ stripped; control, bidi and zero-width characters removed from every string before your handler sees it.

Confirmation gates

requiresConfirmation: true tools refuse to run until a human approves in TkxAgentConfirm. No confirm UI mounted → the tool refuses. Fail closed.

Rate limit + audit

Per-tool token bucket (30 calls / min by default). Every registration, call and refusal lands in the SHA-256 hash-chained audit log.

Declare a tool

Section titled “Declare a tool”

Names are namespace.verb_noun; descriptions must be at least 20 characters because agents choose tools by reading them. The latest handler is always used, so no useCallback is needed. Unmount unregisters.

Expose a whole form

Section titled “Expose a whole form”
Generated toolBehaviour
checkout.describeRead-only — current values, errors, required fields
checkout.fillPartial update; the form’s own rules still run
checkout.submitValidate everything, then onSubmit. Confirmation-gated by default

The agent cannot bypass validation: the schema rejects out-of-range input before it touches the form, and TkxFormField rules run after.

Human in the loop

Section titled “Human in the loop”

The dialog shows the tool, its description and the sanitised input with Allow / Deny. Requests queue; unmounting denies anything pending.

Outcomes an agent can act on

Section titled “Outcomes an agent can act on”

Unknown tools come back with ranked suggestions — the registry never invents one, the same rule the MCP server follows.

Spec status

WebMCP is an early W3C community-group proposal with Chrome and Edge previews; navigator.modelContext may change. This module feature-detects it at call time and never depends on it — the global and DOM manifests work in every browser shipped since 2017.
